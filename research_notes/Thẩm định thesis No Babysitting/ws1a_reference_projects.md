## Q2. ECC (affaan-m/ECC) — what is it, how does it work, and how does it relate to No Babysitting?

### Takeaway
ECC is a very large "agent harness operating system" for developers — 72 agents, 327 skills, hooks, rules, a cross-harness memory vault and "instinct"-based continuous learning — centred on a plan→TDD→review→verify→remember loop in Claude Code. It learns *about the codebase and the user's coding preferences* from sessions, but does not coach the human or evaluate collaboration quality.

### Cited Findings
- [Fact] Purpose/positioning: "Your agent can write code, but ECC gives it a coordinated engineering system and toolbox: it plans before it builds, verifies changes with tests, reviews its own work from a fresh context, remembers what matters… `plan -> test -> implement -> review -> verify -> remember -> improve`"; "Access to 72 agents, 327 skills, and 98 legacy command shims, plus hooks, rules, memory, continuous learning, and AgentShield security scanning" — [README.md](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/README.md).
- [Fact] Interaction model: slash commands/skills chosen by task — `/ecc:plan "describe the feature"` then `tdd-workflow`, `/code-review`, `/build-fix`, `/context-budget`, `/save-session`, `/learn-eval`, `/resume-session` ("Start Using ECC" table) — [README.md](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/README.md#start-using-ecc).
- [Fact] Platform dependency: "works best with Claude Code today, has native Codex and Qoder plugin paths, and provides capability-limited adapters for Cursor, OpenCode, Gemini, Zed, GitHub Copilot, Antigravity, Qwen…"; support matrix marks Claude Code "Stable primary", Codex "Supported native plugin", Cursor/OpenCode "Beta", Copilot Chat "Instruction-only", Gemini/Zed/Hermes etc. "Experimental/minimal" — [README.md § Platform Support](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/README.md#platform-support).
- [Fact] Onboarding: requires Node.js 18+, Git, Claude Code 2.1+; `npx ecc-universal@2.2.3 setup` guided installer; a Windows walkthrough "If you are new to command-line tools"; README warns "Choose one and do not stack a full manual Claude install on top" and the plugin "advertises the installed catalog to the model; use a selective/manual profile when context footprint matters" — [README.md § Install ECC](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/README.md#install-ecc).
- [Fact] Memory: "Memory Vault" — portable `ecc.memory.v1` Markdown under `.ecc/memory/` (project/team) and `~/.ecc/memory/` (user), CLI + optional MCP server (`memory_save/search/read/doctor`), cross-harness handoffs (`ecc memory handoff --from hermes --target codex`); "Memory is unreviewed context, not executable policy… human review promotes accepted knowledge into governed project documentation" — [README.md § Share context between harnesses](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/README.md), [skills/unified-memory/SKILL.md](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/skills/unified-memory/SKILL.md).
- [Fact] Learning loop: `continuous-learning-v2` observes sessions via PreToolUse/PostToolUse hooks, a background Haiku agent creates atomic "instincts" with confidence 0.3–0.9, project-scoped by git remote, promoted to global "when seen in 2+ projects", and "evolves them into skills/commands/agents"; example instinct evidence: "User corrected class-based approach to functional on 2025-01-15" — [skills/continuous-learning-v2/SKILL.md](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/skills/continuous-learning-v2/SKILL.md).
- [Fact] Evaluation: `verification-loop` = six-phase build/type/lint/tests-with-coverage/security-grep/diff-review → PASS/FAIL report — [skills/verification-loop/SKILL.md](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/skills/verification-loop/SKILL.md); `agent-self-evaluation` = agent self-rates its *output* 1–5 on accuracy, completeness, clarity, actionability, conciseness — [skills/agent-self-evaluation/SKILL.md](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/skills/agent-self-evaluation/SKILL.md); `/learn-eval` "self-evaluate quality before saving" extracted patterns — [commands/learn-eval.md](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/commands/learn-eval.md).
- [Fact] Breadth beyond code exists in the catalog (skills such as `article-writing`, `market-research`, `investor-materials`, `marketing-campaign`, `email-ops`, `finance-billing-ops`, `product-lens`) — [skills/ directory](https://github.com/affaan-m/ECC/tree/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/skills).
- [Fact] Extensibility: skills/agents/rules/hooks/MCP configs as files; security scanner AgentShield (`ecc-agentshield` npm) scans prompts, hooks, MCP config, permissions — [README.md](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/README.md).

### Inferences
- [Inference] Classification: **Adjacent** (S1 developer workflow harness) and partly **Conceptual reference** for memory hygiene (unreviewed-by-default memory, project vs. global scope, confidence-weighted learned behaviours) — directly relevant to NB's B5/B6 risk-based adaptation and memory principles.
- [Inference] Overlap with NB: workflow design (plan→execute→review), outcome verification (tests/build gates), and "learning" from sessions. Non-overlap: no problem-framing stage beyond `/ecc:plan`; instincts learn *what the agent should do*, not *how the human collaborates*; no adaptive guidance intensity.
- [Inference] Limitation: catalog scale (327 skills) is itself the "babysitting" problem NB claims to solve — the user must know which of hundreds of surfaces to invoke; the README's own advice ("Start with the workflow you need, not the full catalog") concedes this.
- [Inference] Differentiation opportunity for NB: a *selector/coach* that tells a user which capability (native or ECC-like) fits their problem is something ECC does not do; but ECC is a candidate **integration target**, not something to rebuild.

### Gaps
- Effectiveness data for instincts (do they improve outcomes?) — none found in repo docs read; README makes no measured claims.
- ECC Pro feature set/pricing beyond "$19/seat/mo for private repos" not verified (ecc.tools not fetched).

## Q3. Hermes Agent (NousResearch/hermes-agent) — what is it, how does it work, and how does it relate to No Babysitting?

### Takeaway
Hermes is a full, model-agnostic **personal agent runtime** (CLI/TUI, desktop, messaging gateway for Telegram/Slack/WhatsApp, cron, sub-agents, sandboxes) with a closed self-improvement loop: curated memory files, a user profile (USER.md), autonomous skill creation and an optional Honcho "dialectic user modeling" backend. It is the only reference project that reaches non-technical users through chat apps, but it is an execution runtime — exactly what NB says it will not build.

### Cited Findings
- [Fact] Positioning: "It's the only agent with a built-in learning loop — it creates skills from experience, improves them during use, nudges itself to persist knowledge, searches its own past conversations, and builds a deepening model of who you are across sessions"; "Use any model you want — Nous Portal, OpenRouter, OpenAI, your own endpoint"; "Lives where you do: Telegram, Discord, Slack, WhatsApp, Signal, and CLI — all from a single gateway process"; six terminal backends (local, Docker, SSH, Modal, Daytona, Vercel Sandbox) — [README.md](https://github.com/NousResearch/hermes-agent/blob/27e389359263b7294e2788fee048953fc34b82d1/README.md).
- [Fact] Install/onboarding: `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash` or PowerShell one-liner; then `hermes`, `hermes model`, `hermes setup`; optional paid "Nous Portal" subscription bundles 300+ models and a Tool Gateway (search, image, TTS, browser) via `hermes setup --portal` — [README.md](https://github.com/NousResearch/hermes-agent/blob/27e389359263b7294e2788fee048953fc34b82d1/README.md).
- [Fact] Memory: two bounded files in `~/.hermes/memories/` — `MEMORY.md` (agent notes, 2,200 chars) and `USER.md` ("User profile — your preferences, communication style, expectations", 1,375 chars) — injected as a frozen snapshot at session start; the agent edits them via a `memory` tool; plus FTS5 `session_search`; a documented common failure: "I told it to remember, and the next session it forgot" — [website/docs/user-guide/features/memory.md](https://github.com/NousResearch/hermes-agent/blob/27e389359263b7294e2788fee048953fc34b82d1/website/docs/user-guide/features/memory.md).
- [Fact] Optional Honcho plugin (Plastic Labs): "After each conversation turn… Honcho analyzes the exchange and derives insights about the user's preferences, habits, and goals", per-peer profile separation — [website/docs/user-guide/features/honcho.md](https://github.com/NousResearch/hermes-agent/blob/27e389359263b7294e2788fee048953fc34b82d1/website/docs/user-guide/features/honcho.md).
- [Fact] Skill self-improvement & hygiene: the Curator tracks use of agent-created skills, moves them `active → stale (14 d) → archived (30 d)`, optional LLM consolidation "OFF by default" — [website/docs/user-guide/features/curator.md](https://github.com/NousResearch/hermes-agent/blob/27e389359263b7294e2788fee048953fc34b82d1/website/docs/user-guide/features/curator.md).
- [Fact] Evaluation of outcomes: `/goal` "After every turn a lightweight judge model checks whether the goal is satisfied by the assistant's last response. If not, Hermes automatically feeds a continuation prompt back" (Ralph-loop, inspired by Codex CLI 0.128.0 `/goal`) — [website/docs/user-guide/features/goals.md](https://github.com/NousResearch/hermes-agent/blob/27e389359263b7294e2788fee048953fc34b82d1/website/docs/user-guide/features/goals.md). Repo also has an `evals/` directory of runtime behaviour probes (e.g. `approval_deny_dispatch.py`, `acp_empty_session_wire.py`) — [evals/](https://github.com/NousResearch/hermes-agent/tree/27e389359263b7294e2788fee048953fc34b82d1/evals).
- [Fact] Non-technical deliverables: "Deliverable Mode" sends generated charts, PDFs, `.docx`, `.xlsx` as native attachments in messaging platforms — [website/docs/user-guide/features/deliverable-mode.md](https://github.com/NousResearch/hermes-agent/blob/27e389359263b7294e2788fee048953fc34b82d1/website/docs/user-guide/features/deliverable-mode.md).
- [Fact] Hermes is also a *host* for other reference projects: Superpowers documents a Hermes Agent install — [superpowers README](https://github.com/obra/superpowers/blob/22f0b463e7a5e579904dd6211a520321035526f7/README.md); ECC lists Hermes as an experimental adapter target — [ECC README](https://github.com/affaan-m/ECC/blob/3f14a103a8694e51c1df9a806217a6d0b5f7a6f7/README.md#platform-support).

### Inferences
- [Inference] Classification: **Adjacent** (personal AI assistant / agent runtime) and **Integration partner** (a host NB methodology could run inside, like Claude Code/Codex). Not a direct competitor because it has no problem-framing or coaching methodology.
- [Inference] Hermes' USER.md + Honcho is the strongest *user-modeling infrastructure* among the 8, but it models preferences to personalize the agent, not the user's AI-collaboration capability, and it does not expose a "how well are we collaborating" evaluation. NB's "User Capability Development" dimension is unaddressed here.
- [Inference] Its memory docs are a useful cautionary reference for NB's T2/B6: even a mature runtime struggles with "told it to remember, it forgot", supporting the "prefer native memory, prove need first" principle.
- [Inference] Onboarding friction (shell installer, API keys or paid portal, gateway setup) keeps it a power-user tool despite the messaging-app reach.

### Gaps
- No public data found on Hermes' user mix (how many non-technical users actually use the messaging gateway).
- Effectiveness of the self-improving skill loop is not quantified in the docs read.

## Q4. Hallmark (Nutlope/hallmark) — what is it, how does it work, and how does it relate to No Babysitting?

### Takeaway
Hallmark is a narrow, high-craft **front-end design skill** ("refuses to look AI-generated") for Claude Code, Codex, Cursor and OpenCode. Its relevance to NB is methodological: it shows a strong pattern of **tiered, machine-checkable quality gates + fresh-context review + a public eval harness** for a single outcome type — not problem framing or coaching.

### Cited Findings
- [Fact] Purpose: "A design skill for Claude Code, Codex, Cursor and OpenCode that refuses to look AI-generated"; fifty themes; redesign and audit — [README.md](https://github.com/Nutlope/hallmark/blob/04977e15f3dfd6ee4b74c887dac3eb52665d6c92/README.md).
- [Fact] Verification design: gates in tiers — "The Floor never ships (contrast, focus, reduced motion, invented facts, a broken phone layout). Reflex gates are the defaults a model falls into; a build with a reason may overrule one on the record. ### Inferences
- [Finding] Competitive density by segment: **S1 (developers) is saturated** — 5 of 8 are developer methodologies with overlapping loops, plus ECC's 300+ skills. **S2 (semi-technical)** is touched only by add-ons (BMAD Founder/Creative modules, ECC business skills, Superpowers' "out of software" brainstorming) that still require a coding-agent install. **S3 (non-technical)** is reached only by Hermes (runtime, no methodology).
- [Inference] What remains underserved by these 8: (1) evaluating and developing the *human's* collaboration capability (B4 dimensions 3–4); (2) choosing among native capabilities/tools for a given problem (capability blindness — none recommends external tools/platform features); (3) a zero-install entry for S2/S3; (4) cross-session evidence that framing/coaching improves outcomes vs. a bare model.
- [Inference] Where differentiation is hard/unsustainable: problem-framing prompts (Superpowers/BMAD already strong and free, first-party distributed), workflow templates, verification checklists, file-based memory — all copyable within days and already being absorbed into marketplaces. Even the "adaptive" profile (GSD) is a single command.
- [Hypothesis] NB's most defensible angle against these 8 is not methodology content but (a) the evaluation dataset/feedback loop on human-AI collaboration and (b) an entry point that works for S2 without installing a coding agent — both require WS6 demand validation before investment.
- [Recommendation] For NB experiments, use Superpowers `brainstorming` (and/or BMAD `bmad-facilitate`) as the S1 baseline arm, borrow Hallmark's Floor/Reflex/Finish tiering for outcome rubrics, GSD profile-user's consent + confidence + evidence pattern for any user model, and ECC/CE's "unreviewed by default; promote to durable form" rule for memory.

### Gaps
- Open-issue counts and issue response times (requested maturity metric) unavailable due to GitHub access limits.
- No independent (non-maintainer) evaluation of any of the 8 methodologies' effect on outcomes was found in the repos; broader web evidence on that belongs to WS1b/WS6.
